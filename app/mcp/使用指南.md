# curl2py 工具箱 · MCP 使用指南（大白话版）

> 看不懂"协议""传输"这些词没关系，这份文档只回答两件事：**怎么接上**、**接上之后能干啥**。

---

## 一、这东西到底是干嘛的

你平时干这些活是不是很烦：

- 从浏览器复制一段 curl，要改成 Python 代码；
- 一大坨 JSON 挤成一行，眼睛都花了；
- 两个 JSON 差在哪儿，一行行对着看；
- 接口报签名错误，不知道 MD5 还是 SHA256、要不要 Base64；
- 一个时间戳 `1700000000`，想知道是几号。

以前要打开网页工具，一个个粘进去点按钮。

现在这些活变成 **22 个小工具**，AI 可以直接调。你只要说人话：

> "把这段 curl 转成 requests 代码"
> "这两个 JSON 有啥不一样"
> "帮我把这个 JSON 压成一行"

AI 自己去调工具，把结果给你。**你不需要记任何工具名。**

## 二、怎么接上（三选一，看你啥场景）

### 方式 A：本机直接用（已经配好了）

配置文件 `C:\Users\Song\.workbuddy\mcp.json` 里已经有 `curl2py` 这条。
**你只需要重启一下客户端**，然后在"连接管理"里对 `curl2py` 点一次"信任"。

如果你的客户端要手填，长这样：

```json
{
  "mcpServers": {
    "curl2py": {
      "command": "D:\\conde3.10\\python.exe",
      "args": [
        "C:\\Users\\Song\\.agent\\mcps\\curl2py-mcp\\server.py",
        "--base-url", "http://192.168.0.107:9997"
      ]
    }
  }
}
```

> 这条是"直连"模式：本机起一个转发进程，数据走局域网到玩客云。好处是不依赖容器开没开 HTTP。

### 方式 B：局域网里别的设备连（手机、群晖、同事的电脑）

地址就一个：

```
http://192.168.0.107:9999/mcp
```

客户端支持"远程 MCP / Streamable HTTP"的，直接填这个地址：

```json
{
  "mcpServers": {
    "curl2py": {
      "url": "http://192.168.0.107:9999/mcp"
    }
  }
}
```

**客户端只认 stdio（老版本）怎么办？** 中间套一层转接：

```json
{
  "mcpServers": {
    "curl2py": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "http://192.168.0.107:9999/mcp"]
    }
  }
}
```

> 前提是那台机器装了 Node.js。没装就走方式 A 的思路，把 Python 路径换成本机的。

### 方式 C：先确认通不通（接之前建议跑一次）

浏览器或命令行打开：

```
http://192.168.0.107:9999/health
```

看到 `"status": "ok"`、`"tools": 22` 就说明服务活着。看不到就是容器没起来，看第七节。

## 三、22 个工具，一句话一个

不用背，就当菜单看。**左边是"你想干啥"，右边是"AI 会去调哪个"**。

### 先看看能干啥

| 你想干啥 | 工具名 |
|---|---|
| 这服务活着吗、开了哪些功能 | `toolbox_health` |
| 这工具箱一共能做哪些事 | `toolbox_catalog` |

### 理格式（最常用）

| 你想干啥 | 工具名 |
|---|---|
| JSON 美化 / 压成一行 / 查语法错在哪 | `json_format` |
| 浏览器复制的请求头 → 字典 | `header_to_dict` |
| 一长串 Cookie → 字典 | `cookie_to_dict` |
| Python 的 `{'a': 1}` → 标准 JSON | `python_dict_parse` |
| 压掉 JS 里的注释和空行 | `javascript_clean` |
| 去掉 HTML 里的多余空行 | `html_clean` |

### 搞 URL

| 你想干啥 | 工具名 |
|---|---|
| 拆开看域名、路径、每个参数 | `url_parse` |
| 中文/特殊字符转成 `%E4%B8%AD` | `url_encode` |
| `%E4%B8%AD` 转回中文 | `url_decode` |

### curl 转代码

| 你想干啥 | 工具名 |
|---|---|
| curl → Python requests | `curl_to_python` |
| curl → feapder 爬虫模板 | `curl_to_feapder` |

### 加解密 / 编码

| 你想干啥 | 工具名 |
|---|---|
| Base64 编码或解码 | `base64` |
| MD5 / SHA256 / SM3 算摘要 | `hash` |
| **不知道有哪些算法，先查这个** | `crypto_operations` |
| AES / DES / SM4 加解密、HMAC 签名 | `crypto_process` |

### 找不同

| 你想干啥 | 工具名 |
|---|---|
| 两段文本差哪儿（改了什么字） | `text_diff` |
| 两个 JSON 差哪儿（哪个字段变了） | `json_diff` |

### 时间

| 你想干啥 | 工具名 |
|---|---|
| `1700000000` → `2023-11-15 06:13:20` | `timestamp_to_date` |
| 日期 → 时间戳 | `date_to_timestamp` |

### 可选能力（默认没开，开了才在菜单里）

| 你想干啥 | 工具名 | 状态 |
|---|---|---|
| 图片/文件转成 `data:image/png;base64,...` | `file_to_base64` | ✅ 这台机器**已开**，只能读 `/files` 目录 |
| 在服务器上跑一小段 Python | `run_python` | ❌ **没开**，要开看第七节 |

## 四、最好用的 8 个套路

### 1. curl 转代码：连整理都不用

浏览器 F12 → 网络 → 右键接口 → **Copy as cURL**，整段直接扔给 AI：

> "把这个 curl 转成 Python"

原样的 `-H`、`--data-raw`、`^` 折行符它都能吃。**不要自己删参数、不要自己排版**，删了反而丢信息。

### 2. JSON 挤成一行（塞进命令行/配置文件时最有用）

> "把这个 JSON 压成一行"

反过来想看清结构就说"美化一下，缩进 4 个空格"。

> 小坑：`indent=0` 是"换行但不缩进"，**不是压缩**。压缩要用"压成一行"。

### 3. 两个 JSON 比不同

> "这两个接口返回有啥不一样"

默认只给你**摘要**（新增 3 个、删除 1 个、修改 2 个，外加每个改动点的路径），够看结论。
真要逐行明细，再补一句"给我逐行明细"——不然几十 KB 的 diff 会刷屏。

### 4. 签名算不对：先问清单，再算

不要说"帮我算个 HMAC"，直接说：

> "支持哪些加解密算法？"（它会调 `crypto_operations`）
> "用 HmacSHA256 对这个串算签名，key 是 xxx"

**为什么多这一步**：算法名写错（`sha3_256` 写成 `SHA3_256` 之类）会白跑一轮。先看清单最稳。

### 5. 时间戳：秒和毫秒差 1000 倍

> "1700000000 是几号" → 按**秒**算，得 `2023-11-15 06:13:20`
> "1700000000000 是几号" → 这是**毫秒**，要说明"这是毫秒"

13 位的都是毫秒，10 位的是秒。搞错了会得到 5 万多年后的日期。

### 6. 请求头、Cookie 转字典

从浏览器"复制为 cURL"里抠出头，或者直接复制开发者工具里那一坨：

> "把这些请求头转成字典"

认不出的行它会单独列出来告诉你（比如多行值、奇怪的续行），不会默默吞掉。

### 7. 图片塞进 HTML / JSON

先把图片放到玩客云这个目录：

```
/root/mcp-files/
```

然后说：

> "把 /files/logo.png 转成 data URI"

得到 `data:image/png;base64,...`，直接放进 `<img src="...">` 就能用，不用图床。

> 只能读 `/files` 下面的文件，读别的（比如 `/etc/passwd`）会被拒绝——这是故意的。

### 8. 一次问一串

这些工具都是"算一下、回结果、不留痕"的纯活，**可以连着调**：

> "把这个 curl 转 Python，然后把里面的 token 用 MD5 算一下，再帮我看看两个返回体的 JSON 差异"

AI 会自己排顺序，你不用一个个来。

## 四·五、Cookie 收藏夹：为什么模型看不到它

v0.5.0 起网页端多了一个「Cookie 收藏夹」，可以把常用站点的 Cookie 加密存起来，用时一键复制。
**这个功能故意不对 MCP 开放**，不是漏了：

- 工具表里就没有收藏夹相关工具，`/api/vault` 前缀在客户端代码里是黑名单，调到直接报错；
- 后端认 `X-Client-Name: curl2py-mcp`，带这个头的请求一律 403；
- 收藏夹接口还要一把由主密码换发的票据，模型既没有密码也没有票据；
- 数据库卷只挂在 Web 容器上，MCP 容器的文件系统里根本没有这个文件。

所以正确的用法是：**在网页里存、在网页里取**。要让模型帮忙处理某段 Cookie，
把内容复制出来贴给它，而不是指望它去收藏夹里翻。

顺带一句：Cookie 属于账号凭据，能不经过模型就不经过模型——这也是把它排除在外的主要理由。

## 五、省事的技巧（这几条能少踩一半坑）

1. **别自己拼参数，贴原文最省事。** curl、JSON、Header 都是"原样贴进去"识别率最高，你自己格式化过的反而容易丢东西。

2. **先看目录，再问细节。** 不确定能干吗就问"你能干啥"（`toolbox_catalog`），比瞎试快。

3. **对比类默认给摘要，别一上来就要明细。** 逐行明细只在大文件排查时才要。

4. **报错先读原因，别急着重试。** 这个服务把错误写在正常返回里（`isError: true` + 一句中文原因），不是连接断掉那种。看到"参数 xxx 不能为空""AES 需要 16 字节 IV"就补参数，重试同样的东西只会同样失败。

5. **超限要先截断。** 单段文本 1MB、对比单侧 512KB、curl 256KB。超了会直接告诉你多大，不会偷偷截一半。

6. **`crypto_operations` 是免死金牌。** 任何算法名拿不准，先调它。

7. **文件只能放 `/files`。** 想转的图片先扔进 `/root/mcp-files/`。

8. **一秒钟确认服务活着**：浏览器开 `http://192.168.0.107:9999/health`，`status: ok` 就没问题。

## 六、出问题了对照这张表

| 症状 | 多半是 | 怎么办 |
|---|---|---|
| 客户端里根本看不到这些工具 | 没点"信任" / 没重启 | 重启客户端，连接管理里点信任 |
| 连不上、转圈 | 容器没起来 | 第七节命令重启 |
| 返回 `403 拒绝来自 Origin ... 的请求` | 用**网页**直接连了 | 这是故意的防攻击设计，网页客户端不给出这个地址；要用就加 `--allow-origin` |
| 返回 `503 服务端并发已满` | 同时请求太多（>64） | 等一下重试，一个人用不会碰到 |
| 工具返回"无法连接工具箱后端" | 玩客云上的网页服务挂了 | `docker start curl2py` |
| 少两个工具（22 → 21） | 可选能力没开 | 看第七节 `--allow-local-file` |
| 返回的日期是 5 万年以后 | 毫秒当秒用了 | 说明"这是毫秒" |
| `AES 需要 16 字节 IV` | 少了 iv | 补 iv，或用 `mode=ECB`（ECB 不需要 iv） |
| 中文变乱码 | 编码不对 | 加 `input_format=Hex` 或 `Base64` 试 |

## 七、想开"跑 Python"（默认关着，有风险）

`run_python` 能在服务器上执行任意代码。**默认关闭**，理由是：这台 MCP 没设 Token，
局域网里谁都能连，开了就等于把机器交出去。

真要开，三步，缺一不可。

**第 1 步：让后端允许跑脚本，并给它一个 Token**（两个必须同时给，只给一个后端会拒绝）。

后端容器现在是这个配置（`ENABLE_SCRIPT_RUNNER=false`），要重建一次，其余参数照抄、只加两行：

```bash
docker rm -f curl2py
docker run -d --name curl2py \
  --restart unless-stopped -p 9997:5000 \
  --memory 512m --cpus 3 \
  -e ENABLE_SCRIPT_RUNNER=true \
  -e CURL2PY_API_TOKEN=换成一串随机值 \
  -e CURL2PY_CONVERTER=native \
  -e GUNICORN_WORKERS=4 -e GUNICORN_THREADS=4 -e TZ=Asia/Shanghai \
  curl2py-web:0.4.2-armv7
```

**第 2 步：MCP 侧也打开，并给 MCP 自己一个 HTTP Token**（没有 Token 会拒绝启动）。

改 `/root/run-mcp.sh` 最后那段，加上两个参数：

```
--allow-script-run --http-token 另一串随机值
```

**第 3 步：重启**

```bash
sh /root/run-mcp.sh
```

开完怎么确认？`/health` 里 `capabilities.script_run` 会变成 `true`：

```bash
curl -s http://127.0.0.1:9999/health | grep -o '"script_run":[a-z]*'
```

> 开了之后所有客户端调用都要带 Token（`Authorization: Bearer 那串值`），
> 否则会被 401 挡掉。不开就没这个麻烦。

## 八、日常运维三条命令

```bash
# 活着吗、开了啥、跑多久、多少请求、占多少内存
curl -s http://127.0.0.1:9999/health

# 重启（改完参数都跑这个，重复执行安全）
sh /root/run-mcp.sh

# 看日志（已自动轮转，最多占 20MB）
docker logs --tail 50 curl2py-mcp
```

**自愈是自动的，不用你管**：

- 进程崩了 → Docker 自动拉起（实测 9 秒恢复）
- 容器整个没了 / 卡住不健康 → 看门狗每 2 分钟检查一次，自动重启（日志在 `/var/log/mcp-watchdog.log`）
- 后端挂了 → 工具会返回一句人话错误，MCP 自己不倒；后端回来它自己接上
- 日志写满 → 已限制单文件 10MB、最多 2 个，不会把磁盘写爆
